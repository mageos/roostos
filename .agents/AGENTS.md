# RoostOS UI Design Rules

## Lists of Objects (People, Devices, Locations, etc.)

*   **No Persistent Add Forms**: Do not display a permanent "Add" card or form at the bottom or side of lists.
*   **Inline Editing Row Expansion**: When the user clicks the "Edit" button on a row inside a table list, that row must expand or be replaced in-place by an inline form containing edit inputs for the fields.
*   **Top/Bottom Add Buttons**: To register or add a new object to a list, place "+ Add [Object]" buttons at the top and bottom of the table.
*   **Inline Add Row Insertion**: Clicking the add button must insert a temporary inline row form at the top/bottom of the table body, utilizing the exact same form fields as the inline editing row.
